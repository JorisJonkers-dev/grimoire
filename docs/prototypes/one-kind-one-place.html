One kind, one place

The question: can everything the system needs from one Effect component kind come from a single definition, so that adding a kind adds new files and edits nothing shared, and the builder form needs no hand-written page? The kind definitions below were printed by real Go code, one file per kind. This page builds the form, the checks, the rules text, the Design file and the database rows from those definitions alone. It knows nothing about any single kind.
