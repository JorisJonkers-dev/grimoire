# UUIDs for API identifiers, tokens only in request bodies

The OWASP ruleset in the spec gate fails on numeric identifiers and on credentials in URL paths.
Rather than silence it, every entity the API exposes (campaigns, members, invites and everything
after them) is keyed by a random UUID generated by Postgres, and compendium entries stay addressed
by slug. Guessing an id is then useless even where an authorisation check is missing. Secrets such
as invite tokens travel only in JSON request bodies, and the web app puts them in the URL fragment,
which browsers never send to a server, so they never reach access logs. The cost is wider keys
and keyset cursors ordered by creation time rather than by id.
